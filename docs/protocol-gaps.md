# crosstalk protocol 1.0: implementation gaps

Where the reference implementation does not yet meet `docs/protocol.md`. One line each: protocol says / code does / location.

## Versioning (protocol section 15)

- Discovery: protocol requires unauthenticated `GET /.well-known/crosstalk`; relay has no such route (only `/v1/hello`, `/v1/init`, `/v1/spaces/...`). `src/relay/index.ts:120-134`
- Header: relays MUST send and clients MUST send `Crosstalk-Protocol`; relay sets only content-type and cache-control, client sends only authorization and content-type. `src/relay/index.ts:115`, `src/client/http.ts:69-71`
- Unknown op: protocol answers `unsupported_op`; relay answers `invalid_request` (schema failure) and also `invalid_request` for a schema-valid op without a handler. `src/core/commands.ts:62,66`
- Unsupported major: protocol answers `unsupported_version`; relay answers `not_found`. `src/relay/index.ts:134`
- Receiver tolerance: consumers MUST ignore unknown members and unknown body types (15.4); the exporter and `xt audit verify` validate events with the strict schema (`additionalProperties: false`) and reject them. `src/exporter/index.ts:53,107`, `src/schema/event-schema.ts:6`
- Schema `$id`s: all six Appendix A documents are generated by `src/schema/publish.ts` and published to GitHub Pages; at run time only the event and command schemas carry an `$id`. `src/schema/session-schema.ts`, `src/schema/gate-schema.ts`
- Implementation version: MCP server and package report `0.0.0`; nothing reports the protocol version separately. `src/bridge/index.ts:74`, `package.json:3`

## Commands and state

- `executor.reconcile`: protocol defines it as a human-key op; the schema accepts it but no handler exists, so the relay answers "Operation is not implemented". `src/schema/command-schema.ts:74`, `src/core/commands.ts:52-56`
- Blocking approval asks: protocol requires `bound_head` (and `bound_artifact` for `deploy:` scopes) on an approval ask with `blocks`; relay accepts it without, creating a requirement that only a reaffirm can satisfy (the decision is bound to `null`). `src/core/asks.ts:31,72`
- Question asks: protocol sets `answered` for any valid choice; code sets `rejected` when a question's choice is the string `reject`. `src/core/asks.ts:66`
- Branch state `cleared`: allowed in the event schema and treated as "no status" by the merge gate, but no op produces it. `src/schema/event-schema.ts:80`, `src/core/gates.ts:53`
- Reservation abandon: emitted as a second `reservation` event that differs from the original only by the free-text note `abandoned…`, so consumers cannot tell it apart structurally (protocol forbids acting on free text). Candidate for an optional `abandoned` field in 1.1. `src/core/coordination.ts:25`
- Reachability: `ref.advance` writes no event, so the facts behind `require_on` are not in the log or audit export. Documented as such; consider an event in a later minor. `src/core/coordination.ts:118`
- Relay sweep builds its context from the first space's epoch; per-space helpers override it, but a multi-space relay depends on that override everywhere. `src/relay/index.ts:247`
